# Decisions (ADR) — самообновляемый харнесс

> Номера 6–12 не использованы: решения этого периода записывались в рабочие планы и лог, а не
> сюда. Пропуск оставлен как есть — перенумерация сломала бы ссылки на ADR-13 и ADR-14.

Формат: Контекст / Решение / Последствия. Кратко.

## ADR-1: Гибрид (3 слоя), не монорепа

**Контекст.** Инстансы (abdulpay, fenris, turbo-omni) — отдельные GitLab-репо с разными remote.
Дрейф умеренный (abdulpay≈темплейт, turbo-omni разошёлся, fenris форк).
**Решение.** Не сливать в монорепу. 3 слоя: CORE (синк жёстко) / LANG (по языку) / LOCAL (свобода).
**Последствия.** Синкаем только CORE → нет Copier-конфликтов на локальных правках, работает даже на форке.

## ADR-2: Copier, не cookiecutter / git-subtree

**Контекст.** Нужна раскатка обновлений CORE вниз, не разовый скаффолд.
**Решение.** Copier (`copier update` умеет template→project merge; cookiecutter — нет).
**Последствия.** Зависимость Python/pipx. Хрупкость на конфликтах — митигируется синком только CORE.

## ADR-3: Обратный канал — отдельный процесс, не Copier

**Контекст.** Copier односторонний by design. Нужен подъём улучшений инстанс→темплейт.
**Решение.** `scripts/harness-contribute.sh` копирует CORE-изменения + печатает diff и инструкцию PR.
**Последствия.** Скрипт слеп к направлению (может поднять старую версию) → показывает diff,
git-операции и решение — за человеком. Не автоматизируем PR.

## ADR-4: settings.json — НЕ в CORE-sync (осознанно)

**Контекст.** Структура хуков общая (CORE-природа), но `settings.json` содержит проектные
плейсхолдеры (`<TEST_CMD>`, `<WIKI_PATH>`) и локальные отличия (fenris: свои guard/sensor).
**Решение.** Пока НЕ синкать `settings.json` через Copier. Раскатка — через `.template` при setup.
Якорь путей унифицирован отдельно: все хуки используют `$CLAUDE_PROJECT_DIR` (не `./`, не `${REPO_ROOT}`,
не хардкод) — это исправлено вручную во всех инстансах + темплейте.
**Последствия.** Структура хуков может дрейфовать. Пересмотреть, когда понадобится синк хуков —
тогда нужен аккуратный шаблон с плейсхолдерами, не прямой синк.

## ADR-5: Версия — git-тег темплейта

**Контекст.** Copier версионирует по git-тегам; без тегов пишет `_commit: <hash>` (нечитаемо).
**Решение.** Версия в `VERSION` (0.1.0) + git-тег `v0.1.0` на темплейте для читаемого `copier update`.
**Супердано 23.06:** файл `VERSION` удалён — ручной бамп отставал от тега 4 раза подряд, а copier
читает только теги (VERSION никто не парсил). Единственный источник версии = git-тег `vX.Y.Z`.
**Последствия.** Тег создаёт владелец вручную (git-операции вне зоны агента):
`git -C harness-template tag v0.1.0`.

## ADR-13: Роли-агенты — instance-owned scaffold, не CORE

**Записано задним числом 13.08.** На этот номер ссылались шесть мест (`copier.yml`,
`bootstrap.sh`, `verify-copier.sh`, `verify-bootstrap.sh`, README слоя, runbook доставки), а
записи в реестре не было ни разу — проверка «номера ADR против упоминаний» это и вскрыла.
Формулировка восстановлена по комментариям в этих файлах, не выдумана.

**Контекст.** Роль-агент завязан на стек и базу знаний проекта: fenris переписал `reviewer` под
свои пути и learnings, `bug-triage` — под свой реестр ловушек. Форс-синк такой роли сверху ломает
инстанс, а пустой плейсхолдер в каждом репозитории вреднее явного отсутствия.
**Решение.** `.claude/agents` исключён из Copier-синка (`_exclude`), как и `.claude/docs`.
Раскатка только явным флагом `bootstrap.sh <имя> <lang> --agents` — то есть по осознанному
решению владельца инстанса, а не по обновлению шаблона.
**Последствия.** Улучшение роли не приезжает в инстансы автоматически; подъём и раздача — руками.
Взамен инстанс волен держать свою версию, не воюя с синком.

## ADR-14: Core-роли живут в плагине, шаблон держит только уникальные

**Контекст.** `reviewer` / `scout` / `researcher` / `scribe` существовали четырьмя копиями:
плагин `md-front-skills/core`, `skeleton/.claude/agents/`, и по копии в двух инстансах fenris.
Замер дельты: `scout` и `researcher` идентичны плагину, `scribe` расходится одним словом в
description, `reviewer` — на 13 строк.

**Разбор дельты `reviewer` решил вопрос.** Шаблонная версия заменяла инлайн-чеклист из шести
пунктов ссылкой на `.claude/docs/REVIEW.md`. Но `.claude/docs` Copier не доставляет — значит у
copier-инстанса ссылка битая, а чеклиста нет вовсе. Плагинная версия несёт чеклист внутри и
работает в любом репозитории.

**Решение.** Канон четырёх core-ролей — плагин. Из `skeleton/.claude/agents/` они удалены.
В шаблоне остаётся только то, чего в плагине нет: `bug-triage.md` (уникальная методология
триажа), `Explore.md` (переопределяет встроенный `Explore` ради модели haiku — иначе разведка
идёт по цене модели сессии), `README.md` (документация слоя).

**Последствия.** Инстанс без установленного плагина core-ролей не получит: `bootstrap.sh
--agents` привозит три файла вместо семи. Это записано в README слоя вместе с командой
установки плагина. Взамен исчезает четырёхсторонний дрейф, где правка метода в одной копии
молча расходилась с тремя остальными.
