# Runbook — доставка v0.2.0 на инстансы

**Статус: ПЛАН, не исполнение.** Владелец закрыл правки внутри инстансов; этот файл описывает
процедуру и порядок, чтобы её можно было исполнить осознанно, а не «по памяти».

Шаблон на момент составления: `v0.1.8-13-g21d19c1` (тег не двигали, 13 коммитов поверх).

## Направление дрейфа — главное, что нельзя пропустить

`DIVERGED` в отчёте **не значит «инстанс старее»**. Замер по `turbo-omni`:

| Путь | только в шаблоне | только в инстансе |
|---|---|---|
| `rules/common/git.md` | 10 | 0 |
| `rules/common/methodology-routing.md` | 17 | 0 |
| `rules/common/testing.md` | 71 | 6 |
| `rules/common/workflow.md` | 52 | 14 |
| `guards/gate.sh` | 53 | 5 |
| `scripts/load-context.sh` | 53 | 13 |
| остальные семь | 1–21 | 1–3 |

Два пути безопасны для прямой доставки (в инстансе нет ничего своего). Остальные требуют
разбора, и разбор делится на три случая — их нельзя путать:

1. **Инстанс несёт СТАРУЮ формулировку того же правила.** Проверено на `workflow.md`: 14
   «инстансных» строк — это прежние тексты про независимый ревью и comprehension-gate, которые
   в шаблоне уже переписаны. Доставлять шаблон, ничего не поднимая.
2. **Инстанс несёт УНИКАЛЬНОЕ знание** (свои пути, проектная специфика). Не затирать; место
   такого — LOCAL-слой инстанса, не CORE.
3. **Инстанс несёт УЛУЧШЕНИЕ метода.** Поднять в шаблон ДО доставки, иначе `copier update`
   его затрёт.

Отсюда порядок: **сначала подъём, потом доставка.** Обратный порядок теряет работу безвозвратно.

## Отдельная находка: личный путь в командном репозитории

`turbo-omni/scripts/load-context.sh` содержит захардкоженный абсолютный путь к личной вики
владельца, и файл **закоммичен** в репозиторий инстанса.

Доставка новой версии это чинит: адрес вики переехал в личный конфиг вне репозитория
(`~/.harness/<имя-каталога-репо>.conf`), а сам скрипт стал generic. После доставки нужно:

1. создать личный конфиг с `WIKI_PATH` (одна строка, вне репозитория);
2. убедиться, что в git инстанса больше нет абсолютных путей:
   `git -C <instance> grep -n '/Users/' -- scripts .claude || echo чисто`.

История git инстанса путь всё равно помнит — это не секрет, но знать об этом надо.

## Порядок доставки

### Шаг 0 — preflight (обязателен перед любым `copier update`)

```bash
git -C <instance> status --porcelain   # дерево чистое, иначе update смешает правки
git -C <instance> rev-parse --abbrev-ref HEAD
```

Грязное дерево → остановиться. `copier update` конфликтует хуже, чем merge: он не различает
«моя правка» и «дрейф от шаблона».

### Шаг 1 — поднять дельту инстансов в шаблон

Кандидаты определяются замером выше (случай 3). Инструмент — `scripts/harness-contribute.sh
<instance>`: копирует расходящиеся CORE-файлы в шаблон и печатает diff.

**Он копирует по факту расхождения, без разбора направления** — то есть затрёт свежий шаблонный
файл старым инстансным. Поэтому: прогонять на чистом дереве шаблона, читать `git diff` и
откатывать всё, что не является подъёмом.

Отдельно проверить `fenris`: по записям в TODO там жил AC-протокол ревьюера, которого нет ни в
шаблоне, ни в плагине. Пока протокол не поднят, удалять роли из fenris нельзя — потеряется
единственный носитель.

### Шаг 2 — доставить

```bash
cd <instance>
copier update --trust --vcs-ref v0.2.0      # тег ставит владелец заранее
```

Без тега `copier update` подтянет последний существующий тег, а не текущее состояние — доставка
уедет на полгода назад молча.

### Шаг 3 — включить Ярус 3

`.claude/guards/pre-push.sh` приезжает Copier'ом (он в `CORE_PATHS`), но активацию Copier не
делает. Локально:

```bash
printf '#!/usr/bin/env sh\nsh "$(git rev-parse --show-toplevel)/.claude/guards/pre-push.sh"\n' \
  > .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```

Инстанс с husky — вместо этого `cp` шима из `skeleton/.husky/pre-push`.

### Шаг 4 — дозаполнить конфиг

Новые переменные не появятся сами: `.harness.conf` версионируется в инстансе, Copier его не
трогает. Добавить `SECRET_SCAN_CMD`, `AC_ID_RE`, `AC_TEST_GLOBS`, `AC_TEST_DIR`,
`AC_BASELINE_FILE` — образцы и обоснования в `skeleton/.harness.conf.example`.

Плюс `echo 0 > scripts/check-ac-refs.baseline`: без файла скрипт считает порогом ноль и
предупреждает, что файла нет.

### Шаг 5 — чего Copier не привезёт вообще

Известные гэпы, они же ручные шаги: `.claude/docs/*` (в `_exclude`), `.harness.conf.example`,
`CLAUDE.md.template`, `settings.json.template`, `.husky/`, `.claude/agents/` (ADR-13).
Роли-агенты после ADR-14 берутся из плагина, а не из шаблона.

## Проверка в каждом инстансе

```bash
bash .claude/guards/gate.sh </dev/null; echo "gate=$?"        # </dev/null обязателен
sh .claude/guards/pre-push.sh </dev/null; echo "яр3=$?"
bash scripts/check-ac-refs.sh; echo "ac=$?"
bash scripts/load-context.sh | head -5
git -C . grep -n '/Users/' -- scripts .claude || echo "личных путей нет"
```

Ожидания: `gate=0` на чистом дереве; Ярус 3 либо зелёный, либо честно говорит, что скана нет;
`check-ac-refs` без спек тихо выходит нулём; `load-context` печатает состояние спек.

Отдельно — что дрейф действительно исчез:

```bash
bash <template>/scripts/harness-status.sh <instance>; echo "exit=$?"
```

`exit=1` после доставки означает, что часть путей осталась расходящейся — прочитать список, а не
считать, что «в целом получилось».

## Что не делать

- Не гнать `copier update` до подъёма дельты — потеря работы необратима.
- Не звать `harness-contribute.sh`, не читая его diff: он не различает направление.
- Не копировать файлы `cp` из шаблона мимо Copier: `.copier-answers.yml` останется старым, и
  следующий `update` будет считать инстанс отставшим на те же версии.
- Не заполнять `WIKI_PATH` в `.harness.conf` инстанса — он версионируется.
