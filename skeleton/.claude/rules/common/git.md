# Git — этикет коммитов

Загружается всегда (нет `paths`). Стек-независимо.

- **Коммит только по явному запросу** пользователя («commit»). Не коммитить самовольно.
- **Переносы файлов — `mv`, не `git mv`:** тот неявно стейджит (implicit `git add`),
  а индекс — за владельцем.
- **Не коммитить в дефолтную ветку напрямую** — сначала ветка.
- **Readonly-зоны** (`READONLY_ZONES` из `.harness.conf`) — только через build-команды.
  Guard блокирует прямую запись (exit 2). См. `block-zones.sh`.
- **Не менять манифест зависимостей и лок-файл** без явного запроса.
- `gh` CLI для GitHub-операций (PR, issues).
- **`git merge --no-edit` всегда** — не открывать редактор сообщения слияния.
- **Резолв merge: superset → bulk, не пофайлово.** Одна ветка строго новее/superset другой
  (видно уже на 2-3 core-файлах) → `git checkout --ours <все конфликтные>` разом, промах ловят
  ярусы 2-3 (типы, тесты). Не верифицировать каждый файл вручную: стоило ~20 минут на 16 файлах.
  Ручной разбор оставлять ТОЛЬКО файлам с двусторонними авто-смёрженными добавлениями, где `--ours`
  теряет чужое (пример: `en.json` — feature-ключи `users.sync.*` нельзя терять при выборе HEAD).
  Правка конфликт-маркеров редактированием файла — не git-мутация, делаю сам; сам `checkout`/`merge`
  за владельцем.
