# React / TypeScript — правила (грузятся только на совпавших файлах)

> Расширяет `common/*`, «специфика поверх общего». Здесь только React/TS-специфика;
> workflow, testing-дисциплина и git-этикет не дублируются.
>
> **В монорепе сузь globs до фронтовых директорий,** иначе тулинговый `.ts` в бэкендовом
> пакете притянет реактовские правила. Например: `apps/web/**/*.ts`, `apps/admin/**/*.ts`,
> `packages/**/*.ts` вместо голого `**/*.ts`.
>
> **Инструменты выбираются один раз** (сборщик, роутер, слой данных, стилевая система)
> и фиксируются в `.claude/docs/ARCHITECTURE.md`. Пока решение не записано — не вводить
> библиотеку явочным порядком в одном компоненте: это и есть будущий разъезд. Правила ниже
> от конкретной библиотеки не зависят.

## 1. Архитектура и границы

- **Feature-first, не type-first.** Резать по фиче (`features/booking/…`), а не по технологии
  (`components/`, `hooks/`, `utils/` на весь проект). Общий `components/` растёт монолитом,
  где ничего нельзя удалить, потому что неясно, кто пользуется.
- **Направление зависимостей — в одну сторону:** страница → фича → общий слой. Обратный
  импорт (общий компонент знает про фичу) запрещён; циклический — тем более.
- **Приложения монорепы не импортируют друг друга.** Общее переезжает в общий пакет
  (компоненты) и в пакет контракта с бэком (типы API). Guard это не ловит — ловит ревью.
- **Публичный вход пакета — контракт.** Импортировать пакет через его публичный entry,
  не вглубь по файлам. Внутренняя раскладка пакета — не API.
- **Внутри приложения barrel-файлы не плодить.** Цепочки `index.ts` на каждую папку рвут
  tree-shaking, замедляют HMR и легко создают циклы. Barrel уместен ровно на границе пакета.
- **Переименовываешь экспорт / двигаешь файл → сначала `/rename`.** Реэкспорт через `*`
  рвётся молча, без ошибки компилятора.

## 2. Компоненты

- **Только функции + хуки.** Классовые компоненты — исключение ровно одно: error boundary
  (хуковой замены в React нет; либо готовая обёртка вроде `react-error-boundary`).
- **`React.FC` не использовать** — навязывает `children` и мешает дженерикам.
  Типизировать параметром: `function Card({ id }: CardProps)`.
- **Компонент не объявлять внутри тела другого компонента.** На каждый рендер это новый тип →
  React размонтирует поддерево и теряет состояние и фокус.
- **Композиция вместо prop drilling.** Прокидывание пропа через 3+ уровня — сигнал: передавай
  `children`/слотом или подними владение состоянием, а не расширяй сигнатуры по пути.
- **Условный рендер через `&&` только на булеве.** `items.length && <List/>` отрисует `0`
  на пустом массиве — писать явное сравнение или тернарник.
- **Смена `key` — легальный способ сбросить состояние** поддерева (например, форма при смене
  сущности). Это дешевле и честнее, чем эффект, синхронизирующий стейт с пропом.

## 3. Состояние

- **Классифицировать до того, как выбрать инструмент.** Четыре разных вида, не смешивать:
  - **серверное** (данные из API) — кэш, а не состояние: живёт в слое данных, у него есть
    протухание и инвалидация;
  - **URL** (фильтры, пагинация, выбранная вкладка) — держать в URL, а не в `useState`:
    иначе ломается перезагрузка, «назад» и ссылка, которой делятся;
  - **локальное UI** (открыт ли попап) — `useState` рядом с местом использования;
  - **глобальное клиентское** (тема, сессия) — стор; его должно быть мало.
- **Серверные данные не копировать в клиентский стор.** Две копии = два источника правды
  и ручная синхронизация, которая всегда отстаёт.
- **Состояние поднимать до ближайшего общего родителя, не выше.** Глобальный стор «на всякий
  случай» превращает локальную правку в общерепозиторную.
- **Производное не хранить.** Считается из пропсов/состояния при рендере. `useMemo` — только
  когда замерена реальная цена, а не по привычке.
- **Context — для редко меняющегося.** Любое изменение значения перерисовывает всех
  потребителей: частые обновления через контекст — типовая причина тормозов. Разделять
  контексты (данные отдельно от диспатча).

## 4. Эффекты

- **`useEffect` — это синхронизация с внешним миром** (сеть, подписки, DOM, таймеры).
  Не для вычислений, не для «сделать при изменении пропа», не для трансформации данных.
- **Обработчик события — не эффект.** Реакция на клик пишется в обработчике; эффект,
  срабатывающий от изменения стейта после клика, — окольный путь с лишним рендером.
- **Каждая подписка/таймер закрывается cleanup-функцией.** В dev StrictMode эффект
  монтируется дважды намеренно — если это ломает поведение, дырявый cleanup, а не React.
- **Гонки запросов гасить явно** — флаг `ignore` в замыкании или `AbortController`. Иначе
  медленный ответ перетирает свежий.
- **Массив зависимостей честный.** `eslint-disable react-hooks/exhaustive-deps` — только
  с комментарием «почему». Лишняя зависимость лечится переносом функции внутрь эффекта
  или стабилизацией ссылки, а не глушением линтера.

## 5. Данные и сеть

- **Один слой доступа к данным на приложение.** `fetch` в компоненте руками — только если
  слой ещё не выбран и это записано как временное.
- **Ключи кэша строятся из параметров запроса** — иначе разные фильтры дают одну запись кэша.
- **После мутации — инвалидация затронутых ключей**, не ручная правка кэша «в двух местах».
- **Границу сети валидировать в рантайме.** Типы существуют только при компиляции: на бэке
  поменялось поле — TypeScript промолчит, приложение упадёт в глубине рендера. Схема
  (zod/valibot) на входе даёт ошибку на границе, где её видно.
- **Состояния загрузки и ошибки — часть контракта компонента,** а не «потом добавим».
  Ошибка не проглатывается: либо показана пользователю, либо всплывает в error boundary.

## 6. React 19 API

- **`ref` — обычный проп** для функциональных компонентов; `forwardRef` в новом коде не нужен.
- **`use()`** читает промис/контекст и, в отличие от хуков, может вызываться условно —
  единственное исключение из правил хуков.
- **Формы и мутации — через Actions** (`action` у `<form>`, `useActionState`, `useFormStatus`):
  pending, ошибка и сброс приходят из коробки, вместо трёх ручных `useState`.
- **`useOptimistic`** для оптимистичного UI вместо самодельного отката.
- **`<title>`, `<meta>`, `<link>` рендерятся из компонента** — сторонняя обвязка для head
  не нужна.

## 7. Производительность

- **Сначала замер, потом оптимизация.** Профайлер React DevTools называет виновника;
  `memo`/`useMemo`/`useCallback`, расставленные по интуиции, добавляют цену сравнения и
  прячут реальную проблему.
- **Если включён React Compiler — ручную мемоизацию не писать.** Компилятор делает её сам,
  но только на коде, соблюдающем правила React (чистый рендер, никаких мутаций пропсов
  и внешних объектов во время рендера). Нарушение — он молча пропускает компонент.
- **`key` — стабильный id сущности.** Индекс массива ломает состояние строк при вставке,
  удалении и сортировке.
- **Дробить бандл по роутам** (`lazy` + `Suspense`), а не грузить всё приложение сразу.
- **Длинные списки виртуализировать,** а не «оптимизировать» строку мемоизацией.
- **Не создавать объекты и функции в JSX-пропсах горячих узлов** без нужды — новая ссылка
  на каждый рендер обесценивает любую мемоизацию ниже.

## 8. TypeScript

- **`strict`, без `any` на границах.** `unknown` + сужение вместо `any`; `as` — точечно
  и с комментарием, это заглушённая проверка, а не типизация.
- **Пропсы — именованный экспортируемый тип** (`type XxxProps`) рядом с компонентом.
- **Взаимоисключающие состояния — размеченное объединение,** не набор булевых флагов:
  `{ status: 'loading' } | { status: 'error', error } | { status: 'ok', data }` делает
  невозможные состояния непредставимыми, а `isLoading && isError` — нет.
- **Типы ответа API не объявлять в компоненте** — только в пакете контракта, там же меняются.
- **Расширяешь пропсы DOM-элемента — наследуй его тип** (`ComponentPropsWithoutRef<'button'>`),
  не переписывай список атрибутов руками.

## 9. Формы

- **Одна схема — источник правды** для типов, валидации и сообщений об ошибках;
  дублировать правила на клиенте и в типах нельзя.
- **Ошибка привязана к полю** и связана с ним через `aria-describedby`; сводка сверху —
  дополнение, а не замена.
- **Контролируемость не меняется на лету.** Инпут, стартовавший с `value={undefined}`,
  переходит в контролируемый и роняет предупреждение — начальное значение задавать сразу.

## 10. Доступность

- **Интерактив на нативных элементах** (`button`, `a`, `input`): клавиатура, фокус и роль
  достаются бесплатно — и тесты по роли начинают работать. `div` с `onClick` — недоступен.
- **У каждого поля есть связанный `label`;** placeholder лейблом не является.
- **Фокус после навигации и в модалках управляется явно** — ловушка фокуса в диалоге,
  возврат фокуса на триггер при закрытии.
- **Смысл не передаётся одним цветом** (ошибка = цвет + текст/иконка).

## 11. Безопасность

- **Во фронтовом бандле секретов нет.** Всё, что попало в сборку, видно пользователю —
  включая `VITE_*` / `NEXT_PUBLIC_*`. Приватные ключи живут только на бэке.
- **`dangerouslySetInnerHTML` — по умолчанию нет.** Нужен HTML от пользователя — санитайзер
  на входе и комментарий, почему иначе нельзя.
- **`href`/`src` из данных проверять на схему** (`javascript:` — исполняемый URL).
- **`target="_blank"` только с `rel="noopener noreferrer"`.**

## 12. Стили

- **Хардкод цветов и размеров запрещён** — токены/CSS-переменные. Имя токена сверять
  с конфигом, не угадывать.
- **Стилевая система выбирается один раз** (CSS Modules / Tailwind / CSS-in-JS) и пишется
  в `ARCHITECTURE.md`. Два подхода в одном приложении — гарантированный конфликт специфичности.
- **Глобальные стили — только сброс и токены.** Всё остальное скоупится к компоненту.

## 13. Тесты

- **`vitest` + Testing Library.** Файлы `*.test.tsx` рядом с компонентом или в `__tests__/`.
- **Запрос по доступному имени** (`getByRole`/`getByLabelText`/`getByText`), не по CSS-классам
  и структуре DOM. Тест, падающий от смены вёрстки, — не тест поведения.
- **Взаимодействие через `user-event`, не `fireEvent`** — первый воспроизводит реальную
  последовательность событий (фокус, клавиатура), второй диспатчит один синтетический.
- **Сеть мокать на транспортном уровне** (MSW), а не подменять модуль запросов: так тест
  проверяет реальный путь данных и переживает смену клиента.
- **Проверять то, что видит пользователь,** а не какие хуки вызвались. `waitFor`/`findBy`
  вместо ожидания фиксированного таймаута.
- **Sensor гоняет тесты сам** (`TEST_CMD` в `.harness.conf`, напр. `npx vitest related --run`).
  Пока команда пуста, sensor молчит — и это значит «проверки не было», а не «проверка прошла»:
  прогонять руками и говорить об этом явно.

## 14. Файлы и сгенерированное

- **Компонент — `PascalCase.tsx`, хук — `useXxx.ts`,** тест и стили рядом с ним.
- **Не редактировать** `dist`, `build`, `.next`, `.turbo`, `node_modules`, `coverage` —
  guard блокирует запись (exit 2). Источник правды по списку — `READONLY_ZONES`
  в `.harness.conf`.
- **Lock-файл — артефакт установки,** руками не править. Манифест зависимостей менять
  только по явному запросу (см. `common/git.md`).
