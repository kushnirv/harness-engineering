## Догфуд

**Ярус 3 у этой репы есть.** Раньше тут стояло «нет билда и тест-сьюта, поэтому проверок не
надо» — премиса устарела: сьют есть, **шесть скриптов и около двухсот условий** (замер 18.08:
28 + 9 + 1 + 126 + 26 + 9). Гоняются одной командой:

```bash
bash scripts/verify-all.sh     # ~93s, шесть шагов: синтаксис .sh → Copier → чистота CORE → bootstrap → доки → тесты скриптов
```

Включение на push (git-хук не версионируется, после клона поставить заново):

```bash
cat > .git/hooks/pre-push <<'HOOK' && chmod +x .git/hooks/pre-push
#!/usr/bin/env sh
# Ранний выход на push'ах без объектов: `git push --delete <ветка>` ничего не отправляет, а
# полный сьют — ~50 секунд. Замер 18.08: удаление ветки прогоняло все шесть шагов впустую.
# `[ -t 0 ]` обязателен: без него `cat` при ручном прогоне ждёт EOF и хук виснет.
if [ ! -t 0 ]; then
  REFS="$(cat)"
  if [ -n "$REFS" ] && ! printf '%s\n' "$REFS" \
      | awk 'NF >= 2 && $2 !~ /^0+$/ { alive = 1 } END { exit !alive }'; then
    echo "push только удаляет ref'ы — объектов нет, Ярус 3 пропущен." >&2
    exit 0
  fi
fi
sh "$(git rev-parse --show-toplevel)/scripts/verify-all.sh"
HOOK
```

Проверено на живой операции: удаление двух смерженных веток заняло 2 секунды против ~50 до
фикса. Та же логика лежит в поставляемом `skeleton/.claude/guards/pre-push.sh` и покрыта
четырьмя тестами — догфуд, а не две расходящиеся копии по смыслу.

Проверено в обе стороны: зелёное пускает, долг в CORE отклоняет push. Снять — `rm` этот файл.

**Ярусов 1-2 (sensor/gate) тут нет, и причина не та, что стояла раньше.** Прежняя
формулировка — «пофайлово проверять нечего: билда нет, тестов рядом с файлом нет» — опровергнута
ревью 14.08: `lint-shell.sh` пофайловый по природе, а правки `.sh` тут основной класс изменений,
так что ярус 1 применим вполне.

Настоящая причина — цена: 28 секунд на каждый ход агента дороже пользы, а синтаксис всё равно
ловится на push. Единица проверки у шаблона — вся репа целиком (доехал ли CORE, чист ли он,
сходятся ли доки с кодом), и это не отменяет применимости пофайловой проверки, а объясняет
приоритет. Заведём ярус 1, когда сломанный скрипт реально доедет до инстанса — не раньше.

**Capture-flow догфудим:** `.claude/skills/note/` живой, наблюдения по ходу кидаем в `/note`.

**Догфуд-копии в `.claude/` обязаны совпадать со `skeleton/`** байт в байт — оба набора скилов
видны в сессии одновременно (`plan` и `skeleton:plan`), и расхождение означает работу над
шаблоном по ослабленной версии того, что шаблон проповедует. Держит это проверка в
`check-docs-reality.sh`, не дисциплина.

## Принципы

- **Generic ≠ пустой.** Переносится структура + параметризованные скрипты + методология. Стек и правила — нет.
- **Параметризация вместо хардкода.** Все пути через переменные: `WATCH_DIR`, `READONLY_ZONES`, `TEST_CMD`, `WIKI_PATH`.
- **Dogfood.** Эта репо сама построена по правилам которые проповедует.
- **Mute the green.** Хуки молчат при успехе. Сигналят только при провале.
- **Строй от отказов.** MVP-набор, остальное по реальной боли.

## Поток изменений

```
1. Изменяешь skeleton/ (generic)
2. Применяешь instance в боевом проекте
3. Проверяешь, что боевой проект работает
→ компонент закрыт в обоих репо
```

## Долгосрочная память — два слоя

`.claude/docs/` и внешняя вики решают разные задачи. Это не OR — это AND:

| Слой | Что хранит | Версионируется | Кто читает |
|------|-----------|---------------|------------|
| `.claude/docs/` | Архитектура, паттерны, review-правила | Да (git) | Команда + CI + агенты |
| Внешняя вики (через `load-context.sh`) | Лог сессий, личный нарратив, ADR-мотивации | Нет | Только ты + Claude |

`.claude/docs/` читать по требованию (Read, когда нужно). НЕ `@import`: `@`-ссылка грузит файл в контекст на СТАРТЕ, не лениво — для JIT не годится.
`load-context.sh` — один из вариантов памяти. Можно не использовать вообще.
